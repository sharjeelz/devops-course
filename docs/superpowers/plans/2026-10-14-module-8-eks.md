# Module 8 (Production on EKS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Run Linkly on EKS the production way: a cluster and an RDS database from Terraform, the
database password in AWS Secrets Manager delivered by External Secrets (no secret in Git or Helm
values), HTTPS from cert-manager on the Gateway, autoscaling, Argo CD deploying, and CI that can
plan Terraform with GitHub OIDC (no stored AWS keys). Eight lessons.

**Verification without AWS (the user's standing choice):** an EKS control plane bills ~$0.10/h, so
nothing here calls AWS. Instead:
- **A kind rehearsal** (`app/linkly/eks/rehearse-on-kind.sh`) runs every in-cluster piece for real:
  - a stand-in "RDS" Postgres whose password has URL-hostile characters;
  - External Secrets with its `fake` provider, serving JSON shaped like RDS's managed secret;
  - cert-manager with a self-signed issuer behind an HTTPS Gateway listener (Envoy Gateway);
  - metrics-server and the HPA;
  - checks that Linkly works over HTTPS and the HPA reads CPU.
- **Terraform** for EKS, RDS and the OIDC role, tested with `terraform test` and the mock provider,
  as in Module 7.
- **Chart behaviour** through `helm template` assertions (`app/linkly/helm/test-chart.sh`).

**Tech Stack:** Terraform 1.16.6, AWS provider ~> 6.68, EKS 1.35, cert-manager v1.21.2, External
Secrets v2.12.0, metrics-server v0.9.0 (chart), Envoy Gateway v1.9.2, Argo CD v3.5.5, Helm 4.3, kind 0.33.

**Spec:** `docs/superpowers/specs/2026-10-14-course-design.md`, row 8: "Argo deploys Linkly to EKS;
autoscaling, AWS secrets, TLS; landscape ECS/Fargate". EKS and RDS Terraform comes here, by Module 7's ruling.

## Global Constraints
- Same tagging (`Project=linkly-course`, `ManagedBy=terraform`) and safety rules as Module 7.
- No secret values in Git, Helm values or Terraform state beyond what AWS itself manages:
  RDS `manage_master_user_password = true`.
- The chart stays backward compatible: the defaults still deploy the in-cluster Postgres exactly
  as before (k8s-smoke-test.sh helm and kustomize modes unchanged).
- Lesson header with a **Cost** line. The README states the hourly cost, and that the lessons are
  meant to be done in one sitting, then destroyed.

## Planned rulings
- **No NAT gateway** (~$0.045/h + data). Nodes run in public subnets with public IPs, but their
  security group admits nothing from the internet; RDS sits in private subnets without internet
  routes. Cost if wrong: weaker isolation than a production VPC; the lesson says so.
- **Redis stays in-cluster** (no ElastiCache): it's a cache and queue for clicks, and losing it
  loses at most unflushed clicks. Cost if wrong: one fewer managed service shown.
- **Raw EKS resources instead of the terraform-aws-modules/eks module:** each piece (roles, access
  entries, add-ons, pod identity) is visible and testable with the mock provider. The landscape
  lesson names the community module. Fixes Module 7 lesson 4's claim that Module 8 uses it.

## Review Focus
1. The RDS password contains characters like `@ / : # % +` and must reach DATABASE_URL safely.
   Pinned by the rehearsal's fake secret.
2. Chart defaults must render exactly the old resources. Pinned by test-chart.sh (postgres
   StatefulSet and linkly-db Secret present by default; absent with externalDatabase).
3. The HPA and a fixed `replicas` must not fight: with autoscaling on, Deployments omit `replicas`.
4. HTTPS: the Gateway gets a 443 listener with the cert-manager annotation, and HTTP redirects to HTTPS.
5. The ESO role can read only the one RDS secret; the OIDC role trusts only this repo's main
   branch and PRs.
