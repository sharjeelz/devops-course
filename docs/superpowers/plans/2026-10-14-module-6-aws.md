# Module 6 (AWS Foundations) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Module 6 teaches AWS's foundations: account safety, IAM, regions, VPC networking, EC2, S3 and ECR. It finishes by deploying Linkly on one EC2 instance by hand, on purpose, so that Module 7 can automate it with Terraform. Every AWS-touching lab states its cost up front and ends with a clean-up step.

**Verification without an AWS account (user's choice).** Nothing in this plan calls AWS. The plan verifies everything it can locally:
- **AWS CLI commands.** Every `aws ...` command in the lessons and scripts is checked by the CLI's own parameter validation. `tools/check-aws-commands.sh` runs each one against a dead local endpoint with fake credentials: a well-formed command gets as far as "connect timeout", while a malformed one is rejected before that.
- **The EC2 setup script** runs in an `amazonlinux:2023` container.
- **Running Linkly from GHCR images** (what EC2 does) runs locally.
- **Shell scripts** pass ShellCheck.
- **JSON documents** parse.

What cannot be verified is written plainly in each lesson's notes and in the ledger. The author runs those parts in AWS later.

**Tech Stack:** AWS CLI v2 (2.32 locally), Amazon Linux 2023, Docker plus the Compose plugin v5.6.0, IAM Identity Center, EC2, VPC, S3, ECR, AWS Budgets.

**Spec:** `docs/superpowers/specs/2026-10-14-course-design.md`, module map row 6: "IAM, VPC, EC2, S3, ECR, the CLI; deploy Linkly on EC2 by hand, on purpose; landscape: Azure/GCP equivalents". The spec's cost rule: "every AWS lab opens with a cost warning and ends with a destroy-everything step".

## Global Constraints

- **Lesson format** stays as before. Every header names "Start from: `checkpoint/06-aws`". The README brings the module's files in from `checkpoint/07-terraform`.
- **Cost and clean-up.**
  - The README starts with a cost box: what this module creates, rough prices, and a budget alert as the very first lab.
  - Every lesson that creates resources has a **Cost** line under its header and a **Clean up** section.
  - `app/linkly/aws/cleanup.sh` removes everything the module created. It finds resources by the tag `Project=linkly-course`, plus fixed names for IAM.
- **Tagging.** Every resource the lessons create carries `Project=linkly-course`.
- **Smallest sensible sizes:** `t3.micro`, a single AZ for the hands-on parts, no NAT gateway, no load balancer.
- **No long-lived access keys** anywhere:
  - People sign in through IAM Identity Center with `aws configure sso`.
  - EC2 reaches S3 through an instance role.
  - The root user gets MFA and is then put away.
- **Region:** the examples use `eu-central-1` through `AWS_REGION`, and the lessons say to pick the region closest to you.
- **The by-hand deploy pulls the learner's GHCR images** (from Module 2's pipeline) instead of building on the instance.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A learner forgets to clean up.** `cleanup.sh` must find and delete everything tagged, in dependency order, and say what it removed and what it couldn't. It must be idempotent. Pinned in Task 2: a stubbed `aws` test that records the call order.
2. **SSH open to the world.** The security group allows SSH only from the learner's own IP (`/32`), and port 8080 only from it too. Pinned in Task 4 (lessons), checked by review.
3. **Credentials on the instance.** None. S3 is reached through an instance profile. Pinned in Task 4 (lesson 5).
4. **Amazon Linux 2023 has no Compose plugin.** The install script must download a pinned version, verify its checksum, and fail clearly if anything is off. Pinned in Task 1 (container run).
5. **A command typo in a lesson.** Caught by the offline CLI checker over all lesson code blocks. Pinned in Task 3.

### Task 1: Running Linkly from GHCR on a plain Linux host

- **`app/linkly/compose.ghcr.yaml`:** a Compose override that replaces each `build:` with `image: ${LINKLY_IMAGES}/linkly-<svc>:${LINKLY_TAG}` (both required, with helpful `:?` messages), using `!reset null` on `build`.
  - **Verify:** run `LINKLY_IMAGES=ghcr.io/sharjeelz LINKLY_TAG=sha-85779b4 docker compose -f compose.yaml -f compose.ghcr.yaml up -d --wait` locally. It must pull and become healthy, then shorten and redirect must work. Leaving out `LINKLY_TAG` must fail with the message.
- **`app/linkly/aws/install-docker.sh`:** for Amazon Linux 2023. It runs:
  1. `dnf install -y docker`
  2. `systemctl enable --now docker`
  3. adds `ec2-user` to the docker group
  4. installs the Compose plugin v5.6.0 into `/usr/local/lib/docker/cli-plugins` from GitHub releases, verified against the release's `.sha256` file
  5. prints the versions

  `set -euo pipefail`; it refuses to run if it isn't AL2023.
  - **Verify:** run it in `amazonlinux:2023` with `SKIP_SYSTEMCTL=1` (there's no systemd in a container), and expect `docker compose version` to print v5.6.0. Run ShellCheck too.
- **Commit:** `feat(linkly): run from GHCR images on any Docker host; Docker + Compose installer for Amazon Linux 2023`.

### Task 2: Clean-up script (TDD with a stub `aws`)

- **`app/linkly/aws/cleanup.sh`:**
  - **Scope:** the region from `AWS_REGION` (required). It finds resources tagged `Project=linkly-course`.
  - **Deletion order:**
    1. EC2 instances: terminate them and wait.
    2. Key pair `linkly-course`.
    3. Security groups in the tagged VPCs (except `default`).
    4. Subnets.
    5. Route tables (non-main).
    6. Internet gateways: detach, then delete.
    7. VPCs.
    8. S3 buckets: tagged, or named `linkly-course-*`. Empty them, including versions, then delete.
    9. ECR repositories `linkly-*` tagged for the course: force delete.
    10. IAM: instance profile and role `linkly-course-ec2`, after detaching or deleting its policies.
  - **Behaviour:** it prints each deletion, it is safe to run twice (things already gone are skipped), and `DRY_RUN=1` lists without deleting.
- **`app/linkly/aws/test-cleanup.sh`:** puts a fake `aws` on `PATH` that answers `describe-*`/`list-*` with canned JSON and logs every call. It asserts:
  - the instance is terminated before its security group, and the IGW is detached before deletion and before the VPC is deleted;
  - a bucket is emptied before it is deleted;
  - `DRY_RUN=1` makes no `delete`/`terminate`/`detach` calls;
  - a second run with nothing left exits 0.
- **RED, then GREEN.** Run ShellCheck on both files.
- **Commit:** `feat(linkly): AWS clean-up script for everything Module 6 creates (tested with a stub aws)`.

### Task 3: Offline AWS CLI checker

- **`tools/check-aws-commands.sh FILE...`** extracts each `aws ...` command from fenced `bash` blocks (joining `\` continuations) and from `.sh` files. It substitutes:
  - shell variables with plausible dummy values, by name: `*VPC*`→`vpc-0123456789abcdef0` and so on, `ACCOUNT_ID`→`123456789012`;
  - `$(...)` with a dummy;
  - `<placeholders>` with `x`;
  - `file://` paths, which must exist.

  It then runs each command with fake credentials against `http://127.0.0.1:9`, with `AWS_MAX_ATTEMPTS=1` and short timeouts.
  - **Pass:** the output says "Connect timeout" or "Could not connect", meaning validation passed.
  - **Fail:** anything else, such as unknown options, invalid choices or parameter validation errors. Commands that never contact AWS (`aws --version`, `aws configure sso`, `... help`) are skipped by a short allow-list.
- **Self-test:** a known-bad command (`--instance-typo`) must fail, and a known-good one must pass.
- **Commit:** `test: offline AWS CLI command checker for lessons`.

### Task 4: Lessons

Put these in `modules/06-aws/`. Each lesson that creates resources has a **Cost** line in its header and a **Clean up** section.

- **README**
  - **Cost box:** a `t3.micro` costs about $0.01/h, a public IPv4 address $0.005/h, S3 and ECR cost cents. The whole module, done in a day and cleaned up, should cost under $1. New AWS accounts get Free Tier credits; check the current terms.
  - **First lab:** a budget alert.
  - **Install** the AWS CLI v2.
  - **Bring files in** from `checkpoint/07-terraform`.
  - Note that `cleanup.sh` exists.
- **`01-account-and-iam`**
  - **Concept:** the root user (MFA, then don't use it), IAM Identity Center users and permission sets, short-lived credentials (`aws configure sso`, `aws sso login`), IAM users and access keys (why to avoid them), policies (identity- vs resource-based), least privilege, roles.
  - **Example:**
    - `aws configure sso` (profile `linkly`)
    - `aws sts get-caller-identity --profile linkly`
    - a budget with `aws budgets create-budget` using `app/linkly/aws/budget.json` and `notifications.json`
  - **Lab:** MFA on root · an Identity Center admin user · CLI login with SSO · a $5 budget with an email alert · explain why no access keys.
- **`02-regions-and-vpc`**
  - **Concept:** regions and AZs; VPC, CIDR (10.0.0.0/16), public subnet (10.0.1.0/24), IGW, route table, why private subnets need NAT (and its cost), security groups versus NACLs.
  - **Example** (all tagged):
    1. `create-vpc`, then `create-subnet`
    2. `create-internet-gateway`, then `attach-internet-gateway`
    3. `create-route-table`, then `create-route 0.0.0.0/0`, then `associate-route-table`
    4. `modify-subnet-attribute --map-public-ip-on-launch`
  - **Lab:** pick a region · create the VPC and a public subnet · route it to the internet · explain what makes the subnet "public".
- **`03-ec2`**
  - **Concept:** instances, AMIs (Amazon Linux 2023 via the SSM public parameter), instance types and burstable credits, key pairs, security groups as stateful firewalls, the public IP charge, EBS.
  - **Example:**
    - `create-key-pair --key-type ed25519 --query KeyMaterial --output text > linkly-course.pem`
    - a security group allowing 22 and 8080 from `$(curl -s https://checkip.amazonaws.com)/32`
    - `ssm get-parameters` for the AMI
    - `run-instances` with `t3.micro`, tagged
    - `wait instance-running`, then `describe-instances` for the IP, then `ssh -i … ec2-user@IP`
  - **Lab:** create a key pair and keep it private · open SSH only to your own IP · launch a t3.micro with Amazon Linux 2023 · SSH in and look around.
- **`04-linkly-on-ec2`**
  - **Concept:** deploying "by hand" on a VM, again on purpose (compare Module 0); pulling tested images from the registry; what's missing (no TLS, no backups, one machine, a manual process), which leads into Module 7.
  - **Example:**
    1. `scp` the installer and the compose files.
    2. Run `install-docker.sh`.
    3. Log out and back in (group membership).
    4. Run the `compose.ghcr.yaml` up with your images and tag.
    5. `BASE_URL` set to the public IP.
    6. Open `http://IP:8080`.
  - **Lab:** install Docker on the instance · run Linkly from your GHCR images · use it from your browser · list everything you did by hand.
- **`05-s3`**
  - **Concept:** buckets and objects, globally unique names, Block Public Access, versioning, encryption by default, lifecycle rules, an instance role in place of keys.
  - **Example:**
    - `s3api create-bucket` (with `LocationConstraint` outside us-east-1), `put-bucket-versioning`, `put-public-access-block`
    - an IAM role `linkly-course-ec2` with `ec2-trust.json` and an inline policy from `s3-backup-policy.json` (one bucket only)
    - an instance profile, `associate-iam-instance-profile`
    - on the instance: `docker compose exec postgres pg_dump … | gzip | aws s3 cp - s3://…/linkly-$(date +%F).sql.gz`
  - **Lab:** create a private, versioned bucket · give the instance a role that can only write to it · back up Linkly's database to S3 · explain why no keys are on the instance.
- **`06-ecr`**
  - **Concept:** ECR versus GHCR, private repositories, `get-login-password`, image scanning on push, lifecycle policies; why AWS-native workloads (Module 8) often pull from ECR.
  - **Example:**
    - `ecr create-repository --repository-name linkly-api --image-scanning-configuration scanOnPush=true`
    - `aws ecr get-login-password | docker login --username AWS --password-stdin <acct>.dkr.ecr.<region>.amazonaws.com`
    - tag and push
    - `ecr describe-images`
    - `put-lifecycle-policy` with `ecr-lifecycle.json` (keep the last 10)
  - **Lab:** create a private ECR repository · push your API image to it · read the scan results · add a lifecycle policy.
- **`07-cleanup-and-costs`**
  - **Concept:** what keeps costing money (instances, public IPs, EBS, NAT, idle load balancers), Cost Explorer, budgets, tags for cost allocation.
  - **Example:**
    - `DRY_RUN=1 app/linkly/aws/cleanup.sh`, then for real
    - `aws resourcegroupstaggingapi get-resources --tag-filters Key=Project,Values=linkly-course`, which shows nothing left
  - **Lab:** list what's tagged for the course · run the clean-up script dry, then for real · confirm nothing is left · read your bill in Cost Explorer.

  - **Lab:** map Linkly's AWS setup to one other cloud · name one real difference.
